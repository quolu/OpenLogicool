# Botの時間上限撤去と詰まり通知の1分待機

Windows native・PowerShell 7で修正、focused test、開発版導入、実機起動を確認した。

## 原因と変更

以前の実行は14:08に終了し、状態は「指定時間が終了しました」だった。同梱Bot設定の`DurationMs: 3600000`をHostが起動引数へ渡し、進行と回復監視の両方がその時間で終了していた。

同梱Bot設定と通常起動から時間指定を削除した。runtimeは時間指定がない場合に実行期限を作らない。CLIで計測時間を明示する機能だけを残した。開始記録には実効の時間指定と通知待機時間を保存する。

詰まり検出後は60秒間、担当AIにも決裁箱にも通知せず、既存の操作・画面観測・回復監視を続ける。既知の画面へ復帰した場合は未通知の案件を破棄する。60秒後も続く場合だけ最新画像とOCRで1回通知する。次の詰まりは新たな検出時刻から数える。通知経路を選ぶ前に同じ待機判定を通す。

手入力の優先、提供された停止画像の優先、有限入力、未確認操作の自動再送禁止を変更していない。利用者の停止・画面を閉じた時の終了・通信等の実障害・確定した行動不能による終了も変更していない。

## 検証

- 時間指定省略・明示した有限時間・不正な時間指定の拒否、Hostの停止回収、独立workerの関連21件が成功。
- 詰まりから59,999msは未通知、60,000msで1回だけ通知、期限内復帰で通知破棄、次の詰まりの待機を数え直す試験を含む関連70件が成功。
- Hostの追加試験1件が成功。1分待機の状態でもRunningを維持し、回復観測が増加し、利用者の停止で回収できる。
- `git diff --check`成功。全プロジェクトの通し試験は実行していない。

## 導入と実機

アプリを公開CLIで通常終了し、`scripts/install-development-app.ps1`で開発版を更新した。`installed-hashes.json`でReleaseのHost DLLと導入DLL、Bot設定のソースと導入先がそれぞれSHA-256一致した。

公開CLIの`bot start mabinogi-mobile`で再開した。`bot-list.json`の表示は「時間制限なし」。`live-events.json`の`run-started`は`DurationMs: null`、`AutomaticRulesContinue: true`、`NotificationGraceMs: 60000`。`bot-live.json`でRunning、HP100％、回復観測の増加と約250msの間隔を確認した。

当該実機画面は停止画像に一致しているため入力を待っている。Botの実行終了とは区別する。1時間を超える連続運転と、実ゲーム上で詰まりが60秒継続した後の通知配送は今回未実測。60秒の通知境界と期限内復帰はfocused testで確認した。新たなゲーム操作や通知を試すための意図的な詰まりは作っていない。
