# サイドクエスト受注の流れ（実機の実測 2026-10-10）

マビノギモバイルで、オーナーの口頭の指示に沿って一歩ずつ手で進めた記録。Bot へ組み込む時の材料にする。
窓の大きさは 1713×1117。位置は窓の中の割合（横・縦）で書く。

## 流れ

| 手順 | 操作 | 位置 | 確かめ方 |
|---|---|---|---|
| 1 | 通常の画面で、右の緑の帯の「クエスト＋」を押す | 0.966, 0.201 | 左に地図、右にクエストの一覧が開く |
| 2 | 絞り込みの「サイド」を押す | 0.786, 0.171 | 「サイド」の位置に色つきの背景が付き、下に「エリア」の絞り込みの行が出る |
| 3 | 一覧を一番上まで送る | 0.80, 0.50 → 0.80, 0.65 へ払う | 下の「一番上の見分け方」 |
| 4 | 一番上のクエストの「進行」を押す | 0.914, 0.448 | 地図が閉じ、右の一覧でそのクエストが追跡中になり、キャラが自動で歩き出す |

## 絞り込みのタブ

- 位置は縦 0.171 の行で、横は 全体 0.670・メイン 0.726・サイド 0.786・ショートカット 0.863。
- 選ばれたタブの背景は 全体＝緑・メイン＝オレンジ・サイド＝緑・ショートカット＝水色。選ばれていないタブは暗い背景に灰色の文字。
- 緑は「全体」と「サイド」で同じなので、色だけでは見分けられない。「サイド」の文字の位置に色つきの背景があることで見る。
- 「全体」→「サイド」と押し直しても、一覧は一番上へ戻らない。追跡中のクエストの位置へ移るだけで、その上に約 6,250px（20件ほど）続いていた。

## 一覧の送り方

| 方法 | 1回の動き | 備考 |
|---|---|---|
| ホイール | 51px | 段数を 3 や 5 にしても 51px。1回の送出が1目盛りとして扱われる |
| スライド（着いて止まってから離す）503px | 137〜507px | ばらつく。オーナーの目視では滑っている |
| スライド（同上）168px | 76〜89px | 慣性が乗らない |
| 払う（一定の速さで進み、半分でボタンを離して進み続ける）168px | 298〜466px（多くは 360〜430px） | `game-index flick-points`。操作は約 0.55 秒 |

## 一番上の見分け方

- 一覧の上端の帯（横 0.645〜0.965・縦 0.261〜0.287）の明るさが平ら（行ごとの平均の最大と最小の差が 2 以下）で、帯の上のすき間より 8 以上明るければ、一番上。
- 途中の位置では、上端にぼかしが掛かって濃淡が出る。保存した画面では、一番上の4枚が差 0.00、途中の12枚が差 7 以上。
- **払う前に毎回これを見て、一番上なら送らない。**

## 行き過ぎの失敗（21:30〜21:31）

- 「2回続けて画面が動かなくなったら止める」と決めて払い続けた。
- 一番上でさらに下へ払うと、一覧が止まる代わりに、右の窓そのものが下へ引かれて閉じる。画面が動き続けるので、止まる条件にならない。
- 18回目で一番上に着き、19回目で窓が半分下がり、20回目で閉じ、21〜35回目は地図を 80px ずつ引きずった。
- 閉じた窓は、下の帯の「クエスト」（0.7665, 0.940）を押すと開き直る。一覧の位置と「サイド」の選択は保たれていた。
- 着いて止まってから離すスライドでは、一番上で窓は閉じず、元へ戻った。

## Botへの組み込み（2026-10-11 00:28 の形）

機能 `side-quest`（`fixtures/visual-recovery/mabinogi-20261008/functions/side-quest.json`）。メインの組み合わせに入っている。規則の位置は、窓の枠を除いた描画領域（1711×1085）に対する割合で書く。上の表の位置（窓全体に対する割合）とは縦が約0.02ずれる。

| 規則 | 条件 | 操作 |
|---|---|---|
| `side-quest-start` | 右下のSpaceを押した直後（3秒以内）に「財貨が不足しています」と読め、右上の帯が「クエスト」と読める | 帯を押し、受注の段階へ入る |
| `side-quest-open` | 受注の段階で、右上の帯が「クエスト」と読める（モードから始めた時） | 帯を押す |
| `side-quest-tab` | 「サイド」の文字があり、文字の上の帯が暗い（選ばれていない） | 「サイド」を押す |
| `side-quest-select` | 「サイド」の文字があり、文字の上の帯が緑 | 横0.80・縦0.37（一番上のカードの説明のあたり）を押し、カードの段階へ入る |
| `side-quest-accept` | カードの段階で、ボタンの列（縦0.38より下）に「進行」がある | 一番上の「進行」のカードを覚えて押し、段階を終える |

### 実機の結果

- 2026-10-11 00:32: Space → 0.8秒後と1.6秒後の観測のうち2回目で「財貨が不足しています」を読む → 帯 → サイド → カードの真ん中 → 覚える → 進行。Spaceから進行まで9.6秒。覚えたカードは `live-remembered-card.png`。受注の後、Botは入場の確認（Space）へ進んだ。
- 2026-10-11 00:30: Spaceの直後の知らせは「今は不吉な召喚の結界がありません。出現するまで待機してください。」だった（`step23-after-check.png`）。受注には入らない。

### 分かったこと

- 「進行」の位置のずれ（23:39・23:44 に2回、ボタンの間を押した）は、文字の読み取りではなく、押す位置の選び方が原因だった。読み取りを足すほど同じ場所に文字が重なり、まとめ読みが上下のボタンと周りの文字を1つのかたまりにした。行ごとに読んで一番上の行を選ぶ形に直した。
- カードは、真ん中を押すと開く（目標とお礼が出て、「進行」が濃い緑になる）。開く前のボタンは明るい緑で、文字を読み落とす回がある。
- 「クエスト＋」の帯の地の色は、追跡中のクエストで変わる（緑＝13,179,118・青＝29,176,219・オレンジ＝239,174,66）。3倍に拡大すると3色とも「クエスト十」と読める。
- タブは地域で数が変わる。4つの時の「サイド」の地は窓の横 1296〜1398px、5つ（エリア任務が増える。女神の庭で確認）の時は 1284〜1380px。選ばれているかは、どちらでも地の中に入る帯（横 1306〜1371px・縦 175〜180px、文字の上）の色で見る。
- 一覧を一番上まで払う作りは、利用者の指示（23:18）でやめた。上の「一覧の送り方」「一番上の見分け方」「行き過ぎの失敗」は、やめる前の実測の記録として残す。
- 実機の画面9枚（`side-quest-*.png`）での試験は `tests/OpenLogicool.Host.Tests/SideQuestModeTests.cs`。
