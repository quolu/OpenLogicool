# 進行入力を止めた回復監視と、報酬演出の待機

## 確認済みの結果

キア1Fエリア1は、進行スクリプト停止後に自動戦闘だけでSランククリアした。利用者の「放置したら進む」と一致する。入場や戦闘入力の再送はしていない。

製品に`key-assist --recovery-only --recovery-profile`を追加した。進行workerを起動せず、通常と同じ回復worker・状態保存・Nano経路を使う。停止・障害・取消は従来どおり明示する。回復条件の70％・白20％、待ち時間10秒・5秒は変更していない。

[全観測](recovery-only-measure-events.jsonl)。クリア画面でHUDがないため、これは周期と進行処理の分離の確認。回復専用モードによる戦闘中の実消費は未確認。

## 実利用で再現して修理した欠陥

- 回復監視がクリア説明の「行動不能にならずにクリアしました」を死亡と誤認した。死亡見出しと復活操作の両方を照合する設定に変更。
- 進行規則がクリア説明の「協力ボーナス」を選択画面と誤認した。選択を求める見出しで照合し、誤申請K-N8BV3Pは取り下げた。
- 固定の「画面を押してください」の周囲を背景OCRが拾うたびに操作候補が変わり、入力前の安定確認が進まなかった。一致した固定文言で候補を識別し、本文の変更を追う会話条件は観測文字列を保持する。

Windows OCRを使う実画像試験で、クリア画面はSpace、3択は判断要求、敗北画面は回復終了として区別した。回復専用の進行未起動・取消・障害伝播、固定ラベルの変動と会話本文の区別も試験した。

## Nano送出と利用者判断による待機

`progress-flow011`はNano Spaceを1回送り、クリア結果→宝箱演出→戦利品一覧へ進んだ。[イベント](recovery-only-progress-events.jsonl)。宝箱演出中は「スキップ」だけで次の操作がなく、5秒の結果待ちで停止してK-P5RN84を自動申請した。

利用者回答は「なにもしなくていい場面。待ってれば動く。」。追加のSpace・クリックは送っていない。[戦利品一覧](recovery-only-loot.png)では自動着用・退出ボタンがまだない。

この回答を`WaitForChange`の待機規則へ反映。演出中と操作ボタンのない戦利品表示は低い優先度の待機規則とし、会話・着用・退出の操作条件が現れたらそちらへ移る。回復は並行して継続する。未知画面・選択画面の停止と通知は維持。

Host関連439件成功後、待機規則の追加を含むfocused26件が成功。開発版は正規更新スクリプトで反映し、導入Host DLLとRelease成果物のSHA-256一致を確認した。

待機追加後のHost最終440件も成功。導入版の`progress-flow012`は、約42秒で回復観測166回、進行入力0・回復入力0・判断要求0、process稼働を確認した。[待機中のイベント抜粋](recovery-only-wait-events.jsonl)。この画面に対する常時のAI判断・手動入力は不要となったが、ボタン出現後の進行完了は未確認。

現在の実行は`artifacts/diagnostics-tools/mabinogi-main-20261008/progress-flow012`。実行期限は1時間で、未知画面または判断要求では入力終了後に決裁箱へ通知する。通知の回答はThroughline継続時に`resume_decision`で引き継ぐ。メインクエスト全体の完遂、戦利品表示からの自然進行、完全無人運用は未確認。
