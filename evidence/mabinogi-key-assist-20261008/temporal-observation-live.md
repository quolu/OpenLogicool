# 未知画面を複数回観測してから判断する

利用者の「何秒か画面を見てたら動くものを判定不能と判断するのは早い」「続けてくれ」に従い、固定時間だけの打ち切りを修理した。

## 変更

描画領域を既存の8×8輝度指紋で比較し、平均輝度差6以上の変化で未解決状態の待ち時間と観測数を数え直す。小さい変化は基準画像から累積して比較する。未知画面は少なくとも3回の観測と10秒の変化停止を必要とする。操作後に未知の演出へ入った場合も同様。同じ既知表示が残る場合は5秒の結果待ちを維持し、画像変化で延長する。入力の再送はしない。

会話・報酬・演出固有の名前は画像変化の判定に使わない。確実な選択・敗北、停止画像、回復条件は従来どおり。利用者が待機を指示した既知の戦利品画面では、待機規則を維持して入力しない。

## 再現試験

- 初回・2回目の観測だけでは、時間が経過していても未知画面と断定しない。
- 変化が続く未知画面は34秒まで観測し、最後の変化から10秒経過して初めて判断要求になる。
- 操作後の未知演出が18秒続いても入力せず待ち、次の既知画面へ到着したら結果待ちを解消する。
- 小さい画像差を静止と扱い、ゆっくりした変化は基準画像からの差で検出する。
- 保存されたキアのクリア画面→戦利品一覧の実画像差を検出する。

focused30件成功。最終のHost関連444件成功。開発版へ正規更新し、導入DLLとRelease成果物のSHA-256一致を確認した。

## 導入版での入力なし計測

通常の認識規則を空にした診断用設定を製品の`--measure-only`へ渡し、現在の戦利品画面を未知画面として15秒観測した。診断設定は実行作業ディレクトリ内だけに置き、通常設定を変更しない。ゲームの前面化・クリック・Space・消費入力・決裁申請は0。

| 項目 | 実測 |
|---|---:|
| 進行観測 | 35回 |
| 最初の観測 | 開始900ms |
| 最初の判断要求 | 開始11,281ms |
| 判断要求までの観測数 | 26回 |
| 画像差の最大 | 1.21875 |
| 回復観測 | 59回 |
| 回復観測間隔の最大 | 267ms |
| ゲーム入力・AI呼出し | 0回 |

[全観測](temporal-observation-events.jsonl)。同じ未知画面を約10.4秒・26回観測してから判断要求となった。宝箱やアイテムの小さい光の変化は進行と扱わない。

計測後は通常設定の`progress-flow013`でスクリプトを再開し、52回の進行観測で`loot-wait`を維持、入力0・判断要求0・process稼働を確認。停止画像が優先してOCRを省略する時の観測記録も候補なしとして出力する修正を反映し、最終実行は`progress-flow014`へ引き継いだ。実行期限1時間。未知画面と選択は入力終了後に決裁箱へ通知する。現在の戦利品画面は利用者指示に従い入力なしで待機。ここからの自然進行とメインクエスト全体の完遂は未確認。変化を続ける未知画面は待機を続けるため、一般ゲームのあらゆる停止を自動判定できるとは主張しない。
