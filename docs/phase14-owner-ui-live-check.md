## Computer Useへの操作委任と、検証方法の訂正

ゲームへのクリックは製品のNano USB HID経路で確認する。Computer UseでNIKKEへ直接送ったSendInputの無反応は、その経路の検証になっていなかった。利用者の指摘を受けて検証方法を訂正した。Computer Useは製品UIの操作に使い、ゲーム内入力は製品runtimeに任せる。

Approval Box K-FH4SRUへの回答で、利用者は「もう、コンピュータユーザでお前がやれよ」と操作を委任した。同じ人操作の依頼は再発行しない。標準Computer Useの`@oai/sky`でInput StudioとGame Operatorを操作し、記録タブ、目的入力、記録開始、NIKKE本体への前面切替、記録終了まで実行できた。これはAIによるGUI操作の証拠であり、人が操作したH工程の証拠へ読み替えない。

新しい原本は`demo:0c6219e771c7491bb15a8c179cc73789`、目的「アークからロビー」、開始14:14。NIKKEのロビー画像にあるアークのボタンへ、最新画像で確認した座標を使って2回クリックした。どちらもAPIはエラーを返さず、カーソルは対象ボタン上へ移動したが、次の実画面もロビーのままだった。入力原本には14:16:31と14:17:03の左クリックdown/upが残り、座標はアークの範囲と一致する。原本の取得漏れとゲーム内遷移を区別する。ゲームが遷移しない原因は未解明であり、anti-cheatや権限を原因と断定しない。

Computer Useの公式skillは入力方式をSendInputと説明している。[既存のNIKKE実測](../rag/openlogicool/nikke-sendinput-rejection-2026-08-22.md)では合成キー入力がゲームへ反映されなかった。今回の合成マウス入力の無反応とも整合するが、同じ拒否原因であることは推定に留める。再生排他を外してNanoの出力を新しい利用者デモとして記録する変更は行わない。

記録を実UIで終了し、「原本を保存しました — 記録した画面を解析中 0 / 2 操作」を確認した。原本はローカルの`demonstration-evidence/20261003-141421-424-2a1152ba8248461fa393c588645314b2/`に保持する。既存の利用者操作による往復原本と投影は変更していない。今回のクリックを往復成功や候補マクロ成立として扱わない。

## 製品のNanoクリック確認

製品の`CodexPurposeMacroExecutionEngine`を、受信応答だけを記録する診断用transportと組み合わせて実行した。入力・画面取得・比較・保存は既存の製品runtimeを使い、受信応答の変更や入力方式の切替は行っていない。NIKKEロビーからアークへのNanoクリック1回、実画面の遷移、route版2・1 step、`Completed=true`、`ToolErrors=[]`を確認した。診断実行のrunは`run-20261003-093710-144`。これは製品入力経路の実測であり、人の記録工程やGUI全体の受入の代替にはしない。

その前の製品UI実行`run-20261003-092433-472`はCodex応答のJSON解析エラーで終了した。コンソールからの診断実行で保存した受信261件は有効だったが、GUI再実行ではUTF-8をCP932として復号する不一致を再現できた。子processの標準入出力encodingをUTF-8へ明示し、コンソールなしの試験と導入後GUIの両方で修理を確認した。

続く`run-20261003-093842-384`の前面化失敗は、同名のランチャーを選んでいたことが実測で判明した。対象EXEパスへ照合を修理し、同じ条件でNanoクリック1回により本体の前面化が成立した。開始通知が失敗表示を上書きする欠陥も修理した。`run-20261003-102423-739`は通常起動した製品GUIからロビーへ戻り、`Completed=true`・tool error 0・版2の1手順マクロ保存・実画面とGUI完了表示が一致した。
