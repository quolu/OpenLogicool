## 分かった制約

1. **動かない窓は配信が始まらない。** 取り込みは画面が変わった時だけコマが来る。止まった表示の窓では ffmpeg の送出コマが 0 のまま進まず、path が ready にならず、音も出ない。次の 3 通りで同じだった。
   - 既定（固定コマ数へ複製）
   - 毎秒 30 コマの土台（`color`＋`realtime`）へ `overlay` で重ねる
   - `-fps_mode passthrough -max_interleave_delta 100000`
   ゲームは絵が変わらなくても描き直しを続けるので、コマは届き続ける見込み（マビノギモバイルで 30 秒は確認。長時間は未実測）。届かない場面があるなら、OpenLogicool が一定の間隔でコマを渡す方式（計画で退けた案）が要る。
2. **ffmpeg での読み戻しは遅れの測定に使えない。** RTSP を ffmpeg で読み戻すと約 1.2 秒遅れて見える。読む側の溜めによるもので、WebRTC の視聴では 0.15〜0.17 秒だった。
3. **MediaMTX は既定で MoQ の待ち受けを全ての interface に開く**（:8892／:8893）。使わない受け口は設定で明示して切る（`moq: false`・`rtmp: false`・`hls: false`・`srt: false`）。
4. `gfxcapture` の `resize_mode=scale_aspect` は、縦横比が合わない時に左上へ寄せて黒帯を足す。出力の大きさは窓の縦横比から決める。
