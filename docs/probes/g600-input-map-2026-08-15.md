# G600 input 経路と report 対応表（Deliverable 0B / 2026-08-15 実測）

- 取得経路: user-mode Raw Input（mouse TLC ＋ usage page 0xFF80 RIDEV_PAGEONLY | RIDEV_INPUTSINK）
- device: `HID\VID_046D&PID_C24A`（firmware release 7702）、LGS 9.04.49 稼働環境下
- 一次データ: `probe-output/rawinput-g600-normal-20260815-135438.jsonl`, `rawinput-g600-gshift-20260815-135756.jsonl`, `rawinput-g600-bottomright-20260815-140840.jsonl`, `rawinput-g600-bottomrow-20260815-141033.jsonl`

## 結論: live input route（R-01）

**G600 の全物理入力は、vendor collection (MI_01/COL02) の input report 0x80 として user-mode Raw Input へ届く。確認済み。**
LGS の profile 割当と独立に、1 control = 1 bit の生状態が読める。firmware write なしで全ボタン識別が成立する。

## G-Shift 層の識別（受入条件）

G-Shift 押下中もサイド／クリックの bit 位置は不変で、byte1 bit5 が層を示す。**通常／G-Shift の識別は raw route 単独で成立（確認済み）**。

## legacy 重複の分類（実測）

同一押下に対して次の並行配送を観測:

1. **raw report 0x80**（vendor collection）— 全 control、割当非依存
2. **mouse TLC (MI_00)** — クリック・チルト・ホイールを標準 mouse event として配送（チルトは button4/5 扱い）
3. **LGS 仮想キーボード (PID C232)** — サイドボタン等を現行 profile の割当キー（本環境ではテンキー）として配送
4. G600 自身の keyboard TLC (MI_01/COL01) からの配送は**観測されなかった**（LGS filter が吸収していると推定）

- **サイド中段右端**: 判定完了（2026-08-15 追試 `rawinput-g600-mid4-20260815-143319.jsonl`, `rawinput-g600-mid-reverse-20260815-143730.jsonl`）。

  - 仮説 (c)（押し漏れ）は**棄却**: 順方向掃引（左→右: bit1→bit7→bit2→無音）と逆方向掃引（右→左: 無音→bit2→bit7→bit1）が鏡像で一致し、右端だけが両セッションで再現的に無音。
  - **確認済みの事実**: 中段右端は機械的クリック感があるのに、raw 0x80・LGS 仮想キーボード・mouse TLC の全経路で電気的に無応答。**残る仮説 (a)（スイッチ／配線の故障、または firmware 無効席）が強い推定**。スイッチ故障か firmware 無効かの切り分けは read-only では不能（分解または onboard モード実験が必要）。
