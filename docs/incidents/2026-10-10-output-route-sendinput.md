# G13／G600 のボタンがマビノギモバイルで効かない（出力が SendInput のままだった）

- 発生日: 2026-10-10
- 報告: オーナー「G13 と G600 に設定したボタンがマビノギで発動しない。登録したキーが Nano 経由で送信できていないのでは」
- 状態: 出力の切替は完了。オーナーによる実機のボタン確認は未聴取。

## 原因

常駐の出力経路の設定（`serial-hid-output-settings.json`）が、現在の保存先（`~/.openlogicool`）にも以前の保存先にも無く、既定の SendInput で動いていた（`app status` の `outputRoute=SendInput`、`serial.load` の `requestedRoute=SendInput`）。入力の処理自体は動いていた（処理 256 件・取りこぼし 0）。

Bot は出力が SendInput の時、自分で Nano の接続を開く。そのため Bot の入力はゲームへ届き、G13／G600 に割り当てたキーだけが SendInput で出ていた。マビノギモバイルが SendInput のキーを受け付けないことは、オーナーの報告と切替後の確認で判断する（切替後の確認は未聴取）。

## 対処

1. `bot stop`（Nano の接続試験で接続口を空けるため）。
2. `control invoke serial.save-and-test` で Serial HID と SparkFun Pro Micro を保存。接続試験は成功。反映は次の起動から。
3. アプリの起動し直し（17:13・Bot 担当）。出力が Serial HID になった。

## 対処の途中で出た障害

- **Bot が起動できなくなった（17:13）**: 出力が Serial HID の時、Bot は常駐の Nano の接続を借りる作りだが、借用の入口（`ResidentInputHost.BorrowedNanoSession`）が、起動を遅らせる包みの中の接続を見ていなかった。Bot は自分で接続口を開こうとして、常駐が使用中のため「COM3 を開けませんでした」で異常終了した。この経路は、出力を切り替えたことが無かったため製品の配線では一度も通っていなかった。Bot 担当が a7385a1 で修理し、17:16 に導入して Bot を再開した。
- **事前連絡の欠落**: 本体改良の担当（この記録の筆者）が、Bot 担当へ伝えずに `bot stop` を実行し、続けて起動し直しへ進もうとしてオーナーに止められた。会話どうしの連絡は、相手が受け取りを保留して届かなかった（3 回）。

## 残っていること

- オーナーによる実機のボタン確認（マビノギモバイルを前面にして G13／G600 のボタンが効くか）。
- 出力が Serial HID の間、G13 のボタンを押しても Bot の手入力監視（`WindowsUserInputMonitor`）は手入力と見なさなかった。G13 のキーが Nano から出て、Nano の入力は監視から除外されるため。**修理済み（main）**: 常駐の fast path が物理ボタンの押下数（`FastPathPump.PhysicalHeldCount`）と edge の件数を公開し、監視が観測のたびに読んで手入力として扱う。押している間と、離してから 3 秒は一時停止になる。監視の中で G13 の Raw Input は登録しない（同じ process では最後の登録が勝ち、常駐の受信が止まるため）。導入後の実機確認（Bot 実行中に G13 を押して Bot が手を止めるか）は未実施。
- 出力の設定が未保存の環境では、Nano が接続されていても既定の SendInput で動く。Nano を使うゲームでボタンが効かない理由が画面から分かりにくい。
