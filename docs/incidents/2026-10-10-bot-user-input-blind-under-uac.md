# Botが人の操作を見落とし、操作の最中に割り込んで止まった（2026-10-10）

## 起きたこと

- 19:52:34、Botは戦利品の画面で「退出」をクリックしようとし、Nanoでマウスの矢印を2回動かしても位置が変わらなかったため、processごと止まった。HPの監視も一緒に止まった。
- 担当AIへの通知は「受信箱へ送れません」で失敗し、Botは決裁箱で利用者へ知らせた（K-XNHQ24）。担当AIは利用者の指摘で 20:01 に気づき、20:03 にBotを再開した。
- 利用者の指摘: 操作中のBotの制限が働いていない。マウスの矢印の移動・ホイール・通常のキーボードを検知していない。

## 原因

### 人の操作を見落とした原因（実測）

- ゲーム（MabinogiMobile）は管理者権限（整合性 High）、OpenLogicool.Host は通常権限（Medium）で動いている。
- Windowsは、高い整合性の窓が前面にある間、低い整合性のprocessへキーボードとマウスの入力（Raw Inputと低レベルhook）を渡さない。
- この端末は 15:39 までUACが無効で、Hostも管理者権限で動いていた。UACを有効へ戻した後、ゲームが前面の間のキーボード・マウスの移動・クリック・ホイールがBotから見えなくなった。G13／G600のボタンは、常駐が機器から直接読むので見えていた。
- 根拠:
  - 15:39より前の実行は、Botの送出がNanoの入力として数えられていた（例: 送出19回でNanoの入力149件）。後の実行は、送出を重ねてもNanoの入力の数が増えない（例: 送出33回のうち26回で増えず）。
  - 20:10 の計測で、矢印が1.3秒動いた間、Botの手入力の数は増えなかった。
  - 止まる前の51秒間、Botの記録は入力0件・押下0だった。

### 待ち時間

- Botは、キーとボタンが全部離れてから3秒で送出を再開していた。19:23開始の実行では、利用者の操作の合間（19:45〜19:48）にBotが10回送っていた。

### 矢印が動かなかった原因

- 未特定。その時の矢印の位置と狙った位置を記録していなかった。
- 同じ時刻の出来事: 19:51:23 に別の会話の実験で mediamtx.exe のファイアウォールの確認が出て、19:51:41〜42 に利用者が許可した。19:52:30 に ffmpeg（窓の取り込みとGPUの圧縮）が始まった。因果は確かめていない。

### 通知が届かなかった原因

- 担当の会話が Claude Desktop へ開き直され、Botの通知の宛先（受信箱）が無効になっていた（推測。会話の道具の構成が途中で変わったことが根拠）。`assistant attach` のやり直しで宛先確認の文が届き、以後の通知は届いている。

## 直したこと

- 人の操作が終わったとみなす無入力の時間を3秒から5秒へ変えた（利用者の指定）。`8c2956d`
- クリックの前に矢印を動かせない時は、ボタンを押さず、Botを止めずに手入力があった時と同じだけ待って次の観測でやり直す。1分続いたら担当AIへ知らせる。失敗の文へ矢印の位置と狙った位置を入れた。`8c2956d`
- キーボードとマウスの手入力の監視を、管理者権限で動く監視processへ分けた。対象のゲームがBotより高い整合性で動く時（または対象の整合性を読めない時）だけ使う。
  - 監視processは、押下の数と無入力の時間だけをBotへ渡す。どのキーかは渡さない。
  - Bot自身の入力は、入力元の機器（Nano）で見分けて数えない。G13／G600のキーはNanoから出るが、物理ボタンを常駐が直接見て手入力として数える。
  - 監視が止まった・報告が2秒途絶えた時は、見えないまま続けずに失敗にする。

## 監視の置き場所の作り直し

最初の形（`5e31979`）は、タスクが開発版の置き場所（管理者でなくても書き換えられる）の `OpenLogicool.Launcher.exe` → `OpenLogicool.Host.exe user-input-watch` を管理者権限で起動していた。同じ利用者の通常権限のprocessが、そのフォルダーのファイルを差し替えてタスクを起動すれば、UACの確認なしで管理者権限を得られた。本体改良の会話の指摘で作り直した。

- 昇格するのは、観測だけを行う `OpenLogicool.InputWatch.exe` だけ。project参照ゼロ・Native AOT の単体の実行ファイルで、Hostのexeやdllを読み込まない。
- 置き場所は `%ProgramFiles%\OpenLogicool\InputWatch\`。導入の手順（`scripts/install-user-input-watch.ps1`）が、管理者でない利用者に書き込みの権限が無いことと、所有者が管理者であることを確かめる。
- タスクは、その実行ファイルだけを引数なしで起動する。
- 連絡は監視からHostへの一方通行。Hostは名前つきパイプを読むだけで、監視へ何も送らない。監視は、なりすましを許さない水準（Identification）で開く。Botの出力機器は、監視の中の固定の条件（機器のパスの VID_1B4F と PID_9205／9206）で見分ける。
- 配置と更新は、昇格した導入の手順だけが行う。昇格の前に計算したSHA-256と、置いたファイルを比べる。監視の中身が変わらない導入ではUACの確認は出ない。
- 実測: 通常の.NETのexeは `DOTNET_STARTUP_HOOKS` で差し込んだコードが動いた。Native AOT の `OpenLogicool.InputWatch.exe` では動かなかった。
- 残る割り切り: 同じ利用者の通常権限のprocessが同じ名前のパイプを先に開いてタスクを起動すると、入力の時刻と数は受け取れる（どのキーかは渡らない）。

## 調査中に担当AIが起こした停止

- 20:11、担当AIが動作中の実行の `events.jsonl` を、書き込みと両立しない開き方（`File.ReadLines`）で読み、Botが記録を追記できずに止まった。20:12 に再開した。
- 動作中の記録は `Get-Content`（共有して開く）で読む。

## 確かめたこと

- Hostの試験 741件・構成の試験 8件・同梱の試験 14件が成功。
- 20:38〜21:02 の実行（管理者権限の監視・最初の形）で、利用者の操作78秒の間に手入力の件数が 1175 → 6067 へ増え、入力の空白5秒で再開した。Botが T と B を送った直後に一時停止は起きず、その入力はNanoの入力として数えられた（0 → 8件）。
- 21:03 に作り直した形を導入した。Botの記録に「手入力の観測元=管理者権限の監視process 対象の整合性=0x3000 Botの整合性=0x2000」が出て、`OpenLogicool.InputWatch` のprocessが動いている。タスクの実行ファイルは `C:\Program Files\OpenLogicool\InputWatch\OpenLogicool.InputWatch.exe`、引数なし。
- 作り直した形でも、利用者の操作中（21:04〜21:05）に手入力の件数が 23 → 1065 へ増え、Botは一時停止した。
