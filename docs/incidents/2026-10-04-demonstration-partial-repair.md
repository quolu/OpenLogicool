# 操作デモの部分修復

## 原因と仕様

候補作成がStayed／Undeterminedを除外し、同一遷移も全体で重複排除していた。利用者の51操作のうち47操作がUndeterminedの場合、候補には4操作しか残らず、元の順序を再生できなかった。全操作を保持し、問題の一手だけを直す仕様変更が承認された。

候補は記録順の`RecordedSteps`と観測済みの`EdgeIds`を別に保存する。確認待ちでも候補保存を受理し、重複を含む全操作を残す。原本は変更しない。

記録画面の「選んだ手順を確認・修復」で前後の保存画像を表示し、期待する画面変化あり／なしとメモを新版へ保存する。この利用者指定は実観測のMovedやVerifiedへ昇格しない。操作後画像がない手順は一手だけ再記録し、停止後に元の位置へ差し替える。多操作を再記録した場合は差し替えを拒否し、原本と旧候補を保持する。

再生は既存10基盤・Nano・10秒Compareを使う。確認待ちの一手は入力前に停止し、後続手順を飛ばして完了しない。利用者指定の結果は毎回比較し、不一致ならその一手の修復を案内する。観測済み遷移の非遷移は従来どおりAI監視でその一手だけ修復する。マクロ画面の「開始する手順」から修復後の位置を指定し、完了済みの先行操作を再実行せず続けられる。

- 確認済み: 50手順中25番だけ未判定の候補作成、個別の期待結果保存、一手再記録による差し替え、残り49手順・原本JSON・旧版の不変、SQLite再open。
- 確認済み: 未判定手順で入力前停止、後続を飛ばさない完了判定、変化なし指定の実Compare、不一致停止、指定位置からの再開、確認済み手順だけのAI修復と後続保持。
- 確認済み: Windows native全22テストプロジェクト、1,423件通過。追加の記録候補からマクロ画面へ移るUI回帰試験も通過。正規開発版installerで導入。
- 確認済み: 正規開発版UIで日課の全51操作を版1へ保存。手順1の前後画像を表示し、商品案内のウィンドウが開く期待結果をベルが指定して版2へ保存。ほかの50手順・構造edge列・版1が不変。期待結果の指定は実再生のMovedへ昇格していない。現在46手順が確認待ち。
