# マビモバのメインクエスト進行

## 合意した操作

- 利用者が示した緑の丸と白い四角の停止画像を最優先し、表示中は入力しない。
- 停止画像がなくSpaceの文字があればSpaceを送る。
- どちらもない場合は10秒前後のブレを入れてSpaceを送る。
- 通常間隔のSpaceで画面が切り替わらなければ入力を止め、画面を確認する。判断できない場合はすぐApproval Boxへ申請する。
- 「画面を押してください」の表示でもキーを送る。
- 普段の判定はスクリプトで処理する。ゲームのキー・クリックはNano経由で送る。

現在はラビ2Fエリア3の焚き火前で座り、ルーン刻印・刻印強化・刻印再設定・料理・フードを食べるのボタンが表示されている。緑の停止アイコンが出たまま動かない。run016は停止画像優先の条件を維持して終了済み。休憩画面でのSpace例外か待機かをApproval Box **K-RJ58VW**へ申請し、回答待ち。回答後は最新画面を取得してNanoで実行する。申請を再作成しない。

利用者の継続方針は、実際にゲームを進めながら、確認できた例外操作を画面条件と組にして徐々にスクリプトへ移すこと。停止画像・文字条件・通常間隔・変化なし停止はスクリプトで実測済み。ネコ商人スキップ・戦利品退出・自動着用の例外処理はまだ操作者判断であり、スクリプト化済みと扱わない。

直近の前面化失敗では、クリック前のforegroundがChrome Remote Desktopの`remoting_desktop.exe`、タスクバークリック後がCodexで、ゲームが最小化したことを診断ログで確認した。リモート接続時の前面状態との関係を示す証拠であり、接続だけが根本原因と確定したわけではない。Nano Alt+Tabで前面を復元して続行した。根治修理は未実施。

## 実測と未確認

- 確認済み: Nanoの単発キー入力、停止画像の一致中にキーを送らない判定、決定ボタンのSpace文字のOCR検出、「画面を押してください」のOCR検出、通常間隔の入力後に変化なしで停止する経路。
- 確認済み: 1分の実走で通常入力5回。送出間隔は約11.3〜12.2秒。入力のACKをゲーム内成功として扱わない。
- 未確認: 全画面・全サイズでの文字検出と画像検出、一般ゲームへの適用、メインクエストの完走。
- 未解明: 前面化の際にタスクバークリック後、ゲームが最小化する事象が1回発生した。入力を停止し、診断へ前面プロセス・タイトルを追加した。根治済みとは扱わない。
