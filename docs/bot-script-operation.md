# アプリからBotを起動・停止する

Input Studioの下部にある「Game Operator」を開き、「Bot」タブを選ぶ。「マビノギモバイル 自動進行」を選択し、「Botを開始」で実行する。「Botを停止」は入力と監視の終了を待ってから「停止済み」へ変わる。

Game Operatorを閉じた時もBotは停止する。Input Studioの設定画面は残る。アプリ自体の終了時もBotを回収してから常駐入力を終了する。次のアプリ起動やタブの開き直しでBotを自動再開しない。

画面に表示するもの:

- 開始中、実行中、停止中、停止済み、画面の確認待ち、エラーの区別。
- 現在のHP。HUD非表示・未判定をHP100％やHPゼロへ置き換えない。
- 回復観測回数と直近の観測間隔、進行入力・食事・ポーション・包帯の実送出回数。
- 停止理由と「記録フォルダーを開く」ボタン。

## 既存Botとの関係

以前の`game-index key-assist`と同じ`VisualKeyAssistRuntime`をアプリ内で呼ぶ。別のゲーム操作実装や外部shellを作らない。CLIは従来どおり利用できる。Nanoの通常入力が常駐している時はその接続を借用し、それ以外はBotが接続・解放する。有限入力を使い、停止要求は画像取得・OCR・待機へキャンセルとして伝える。

記録・マクロ再生とBotは同じ排他を共有する。既に実行中なら新たに開始しない。画像判定やゲーム操作はHostが担当し、Desktopは表示と操作要求だけを担当する。

現在同梱するのは、これまで実機で作成したマビノギモバイルの設定。停止画像優先、Space表示と8〜12秒間隔、毎秒4回の回復監視、ポーションHP70％以下、包帯の白20％以上、既存の食事・会話・報酬・退出・停滞観測の判定は変更していない。最長実行時間は60分。通常判定にAIは呼ばない。

## 設定と記録

`BotScripts/MabinogiMobile/`へ設定と必要な参照画像を配布する。判定設定の正本は既存fixtureであり、ビルドと公開時に同じファイルを同梱する。実行に開発repoや`fixtures/`のパスは不要。

Botの記録と回復品の待ち時間は、アプリのDBと同じフォルダー内の`bot-runs/`に保存する。標準起動は`%LOCALAPPDATA%/OpenLogicool/bot-runs/`。各実行の`events.jsonl`は観測と送出、`status.json`は終了状態、正常終了・確認待ちの`result.json`はruntime結果。旧CLI実行の記録を上書きしない。

DBと同じフォルダーに`bot-review-mcp.json`があれば、既存の確認通知接続を使って停止後に決裁箱へ通知する。形式はCLIの`--review-mcp`と同じ。設定がない環境ではアプリ内の停止理由を確認する。今回の端末は既存の接続設定をこの場所へコピーして継続利用している。接続設定は配布物やGitへ含めない。

判定不能の改善とゲーム進行の追加は、今回のアプリ接続後の作業とする。起動・停止機能の実測は[受入記録](../evidence/bot-app-control-20261008/acceptance.md)を参照。
