# アプリからBotを起動・停止する

Input Studioの下部にある「Game Operator」を開き、「Bot」タブを選ぶ。「マビノギモバイル 自動進行」を選択し、「Botを開始」で実行する。「Botを停止」は入力と監視の終了を待ってから「停止済み」へ変わる。

Game Operatorを閉じた時もBotは停止する。Input Studioの設定画面は残る。アプリ自体の終了時もBotを回収してから常駐入力を終了する。次のアプリ起動やタブの開き直しでBotを自動再開しない。

起動中のアプリへ`OpenLogicool.Host.exe bot start mabinogi-mobile`、`bot stop`、`bot status`でも操作できる。全機能の操作一覧・引数・実行状態取得は[CLI操作](application-control-cli.md)を参照。

手元のマウス移動・クリック・ホイール・キー入力やリモート操作を検出したら、Botの前面化と送出を一時停止する。画面観測は続け、全キー・ボタンが離されて3秒間入力がなければ再開する。Nano自身の入力は除外する。画面には「手入力で一時停止中」と表示する。

画面に表示するもの:

- 開始中、実行中、確認事項あり・動作継続中、停止中、停止済み、エラーの区別。
- 現在のHP。HUD非表示・未判定をHP100％やHPゼロへ置き換えない。
- 回復観測回数と直近の観測間隔、進行入力・食事・ポーション・包帯の実送出回数。
- 停止理由と「記録フォルダーを開く」ボタン。

## 既存Botとの関係

以前の`game-index key-assist`と同じ`VisualKeyAssistRuntime`をアプリ内で呼ぶ。別のゲーム操作実装や外部shellを作らない。CLIは従来どおり利用できる。Nanoの通常入力が常駐している時はその接続を借用し、それ以外はBotが接続・解放する。有限入力を使い、停止要求は画像取得・OCR・待機へキャンセルとして伝える。

記録・マクロ再生とBotは同じ排他を共有する。既に実行中なら新たに開始しない。画像判定やゲーム操作はHostが担当し、Desktopは表示と操作要求だけを担当する。

現在同梱するのは、これまで実機で作成したマビノギモバイルの設定。通常移動のSpaceは8〜12秒間隔。会話はこの間隔から分離し、認識した台詞が600ms安定したら送る。直前と同じ台詞には再送せず、停止画像を優先する。スキャンは撮影・OCRと250ms待機の組合せで、実測では毎秒約2回。毎秒4回の回復監視、ポーションHP70％以下、包帯の白20％以上、既存の食事・報酬・退出・停滞観測は維持している。最長実行時間は60分。通常判定にAIは呼ばない。

右下の緑のコンパスと「Space」の表示は、利用者提供画像の固定部分だけを照合し、OCR・通常間隔・600msの安定待ちを使わず検出した回でSpaceを送る。針の回転と周囲の揺れは比較に含めない。送出直前の画像でも表示を確認する。同じ表示のままでは再送せず、600ms以上消えるか白い四角の停止表示へ変わった後、次にコンパスが現れた時に再び送る。手入力の一時停止と停止画像はこの規則より優先する。ウィンドウが前面にない場合は、ゲームを前面に戻してから入力する。

「発見した戦利品」の見出しが10秒続き、自動着用や退出などの操作ボタンが見えていない場合は、Spaceを1回送って報酬表示を進める。周囲の報酬演出やキャラの動きでこの時間を数え直さない。送出直前にも同じ表示を確認し、表示済みの自動着用・退出はこのSpaceより優先する。同じ表示へのSpaceを連打しない。

商人のサービスメニューは、下部の「商店」「世間話」「会話終了」「ESC」が揃った時にEscで閉じる。過去にNanoで突破した終了操作を規則へ残したもので、通常会話のSpaceより優先する。商店・修理・くじなどの消費操作はこの規則では選ばない。

NPCの会話メニューで、クエストの「!」印と、右側の商店・世間話・会話終了が揃った場合は、左側のクエスト項目を選ぶ。クエスト名やNPC名を固定せず、印と配置を確認して表示中の項目文字からクリック位置を求める。印がないメニューではこの規則を使わず、商人の終了規則より優先する。

クエスト項目の表示やクリック成功は、条件充足・クエスト完了を意味しない。「クエストに必要なアイテムがありません」の表示では、その場で再入力をせず、画面観測と回復監視だけを継続する。不足品の入手方法と必要数を確認してから次へ進む。入手方法の案内を見ただけで、所持数の増加を確認済みとしない。

利用者の指示により、会話画面の下部に「承諾」と「やめる」が揃った場合は「承諾」をクリックして進める。回転する会話待ちの印よりこの選択を優先し、NPC名や台詞は条件にしない。「承諾」だけの表示や会話本文に書かれた文字は、この規則の対象にしない。

## 設定と記録

`BotScripts/MabinogiMobile/`へ設定と必要な参照画像を配布する。判定設定の正本は既存fixtureであり、ビルドと公開時に同じファイルを同梱する。実行に開発repoや`fixtures/`のパスは不要。

Botの記録と回復品の待ち時間は、アプリのDBと同じフォルダー内の`bot-runs/`に保存する。標準起動は`%LOCALAPPDATA%/OpenLogicool/bot-runs/`。各実行の`events.jsonl`は観測と送出、`status.json`は終了状態、正常終了・確認待ちの`result.json`はruntime結果。旧CLI実行の記録を上書きしない。

## 確認通知があっても操作規則を続ける

アプリのBotは、確認事項があっても通常Space、次の既知の会話・クリック、画面観測、毎秒4回の回復監視を続ける。通知を実行全体の保留条件にしない。画面には「確認事項あり・動作継続中」と理由を表示し、停止ボタンは使える。開始ボタンは二重起動を防ぐため無効のまま。ボーナスなど回答が必要な選択はその選択だけを待ち、他の処理まで終了しない。

通常プレイのHUDが読める時は、通常Spaceの約1秒後の画面差が小さいだけでは確認申請を出さない。同じ未確認の台詞・ボタンへの再送抑止と停止画像優先は維持する。通知は1回にまとめ、記録は`review-001/`などに保存する。別の既知の表示へ戻ったことを600ms継続して認識した時は、未決の確認申請を取り下げる。通知の送信・取り下げに失敗しても操作規則と監視は継続する。

食事・包帯の効果待ちでもポーション判定を続ける。効果を確認できなかった品だけ追加使用を保留し、保留状態は保存する。HPが読めない時はHP依存の使用をせず観測を続け、進行を巻き添えにしない。これらは状態表示と記録へ残し、判断を要しない不明点を決裁事項にしない。

利用者の停止、アプリの終了、60分の実行期限では処理を終了する。Nano接続・送出の障害と、確定した死亡による終了は維持する。CLIでアプリと同じ動作を使う場合は`--continue-on-review`を指定する。既存の`--keep-monitoring-on-review`は進行を保留して監視だけを続ける従来動作のまま。指定しないCLIの終了動作も従来どおり。

DBと同じフォルダーに`bot-review-mcp.json`があれば、既存の確認通知接続を使って停止後に決裁箱へ通知する。形式はCLIの`--review-mcp`と同じ。設定がない環境ではアプリ内の停止理由を確認する。今回の端末は既存の接続設定をこの場所へコピーして継続利用している。接続設定は配布物やGitへ含めない。

判定不能の改善とゲーム進行の追加は、今回のアプリ接続後の作業とする。起動・停止機能の実測は[受入記録](../evidence/bot-app-control-20261008/acceptance.md)を参照。
